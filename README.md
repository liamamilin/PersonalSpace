# PersonalSpace — 原生 macOS 个人数字空间

**开发规格 v1.1（能力优先版）｜2026-10-28**

> M1–M10 的本地能力已实现：原生文件资料库、授权持久化、搜索预览、个人对象、关联与托管副本，以及四类事务、按需识别、事实校对、待办、本地系统提醒、显式正文搜索、Photos 只读关联、敏感标记、备份恢复、快速收纳与授权文件夹自动更新。后续章节保留原始产品规格。

## 运行

需要 macOS 26+；本轮使用 Xcode 27.1（Swift 6.4、macOS 27 SDK）构建，部署目标为 macOS 26。打开根目录的 `PersonalSpace.xcodeproj`，选择 `PersonalSpace` scheme 后运行。Debug 使用本机 ad hoc 签名，App Sandbox 始终开启；首次构建需要从官方仓库下载固定版本 GRDB 7.11.1。

```bash
xcodebuild -project PersonalSpace.xcodeproj -scheme PersonalSpace \
  -configuration Debug -destination 'platform=macOS' \
  -derivedDataPath .build/DerivedData \
  -clonedSourcePackagesDirPath .build/SourcePackages build
xcodebuild -project PersonalSpace.xcodeproj -scheme PersonalSpace \
  -configuration Debug -destination 'platform=macOS' \
  -derivedDataPath .build/DerivedData \
  -clonedSourcePackagesDirPath .build/SourcePackages test
```

XCTest 会临时重签宿主应用；测试后请再次执行上面的 `build` 命令，恢复普通沙盒签名后再做手工验收。

在 Finder 打开 `.build/DerivedData/Build/Products/Debug/PersonalSpace.app`，或直接用 Xcode Run。此为本地开发构建。`scripts/package_release.sh` 可打包本地 ad hoc 签名 Release ZIP；未做 Developer ID 签名、公证和干净账户验收。

### M1 基础操作

1. 启动时没有演示数据，点击「添加文件夹」，依次选择 `fixtures/M1/A` 和 `fixtures/M1/B`。这些是明确标记的合成测试文件，应用不会自动导入。
2. 按 `⌘F` 搜「订单」，选择 PDF，右侧显示真实系统预览；点「系统预览」或按空格放大，点「在 Finder 中显示」定位原件，点「打开原件」使用默认应用。
3. 搜「合同」，看到 B 中的 `租赁合同.txt`；可点侧栏按来源筛选，点表头或工具栏排序菜单排序。
4. `⌘Q` 退出后重新打开，来源与索引仍在，启动自动补扫。`⌘,` 打开来源设置，可刷新、停止扫描、重新授权和移除来源。
5. 仅把 `fixtures/M1/A/订单样例.pdf` 移到 A 外的测试位置：应用运行时自动更新，旧记录保留并显示不可用；放回后恢复同一条记录。手动刷新仍保留。不要用个人原件做移动测试。

数据库位于应用沙盒的 `Application Support/PersonalSpace/Library.sqlite`。保存来源书签、文件元数据、个人对象与关联、托管副本路径和校验值，不自动读取正文、不联网、不移动或修改原件。来源目录书签始终以只读方式保存；M6 为保存用户选定位置的备份启用 user-selected.read-write。M3 仅在点击识别后处理单份凭证，保存用户选择的事实与出处片段，完整识别原文默认只在当前编辑会话展示；M4 只有在用户点击明确保存正文后才进入全文索引。默认跳过隐藏文件、目录包及所有符号链接。失败或停止的扫描保留原有可用状态。一次显示 500 个查询结果，可点底部「显示更多」。

实现入口：`PersonalSpace/App/PersonalSpaceApp.swift`；界面与扫描在 `PersonalSpace/Library`；唯一数据层在 `PersonalSpace/Data`；来源设置在 `PersonalSpace/Settings`。测试位于 `PersonalSpaceTests/LibraryTests.swift` 和 `PersonalSpaceTests/ObjectAndArchiveTests.swift`。

## M2：个人对象与托管副本

1. 在「个人对象」中点创建，或按 `⌘N`，填写「我的电脑」、设备类别和备注。
2. 点「添加已有资料」，按住 `⌘` 多选 A 中的 `订单样例.pdf` 与 B 中的 `电脑发票.txt`，关联后直接在对象中查找、预览和打开。M2 为 B 新增了一份明确标记的合成发票，当前测试来源共 4 个文件。
3. 选中订单，点「保存副本到资料库」。复制在后台完成，先比对 SHA-256，再提交 SQLite，原文件不移动、不修改。详情分别提供「打开原件」和「打开托管副本」。
4. 仅将合成测试订单移到 A 外后刷新：原件显示不可用，托管副本仍能预览和打开。退出重启，个人对象、两份关联及托管副本仍在。将测试原件放回并刷新可恢复原件访问。
5. 可从资料详情关联到另一个对象、解除某一条关联，或返回资料库。解除关联不删除资料。移除来源停止扫描与访问，保留对象关联和托管副本；从「已托管」可找到副本，重新添加原目录会恢复原来的文件记录。

托管位置为沙盒内 `Application Support/PersonalSpace/Vault`。不做自动去重、源文件删除、内容寻址或后台全盘哈希。实际验证见 [M2 证据](evidence/M2/README.md)。

## M3：订单、事实与系统提醒

1. 添加 `fixtures/M3`，选择 `订单识别样例.png`，在详情点「从此凭证创建订单」（或 `⇧⌘N` 手动创建）。这些都是合成文件，不会自动导入。
2. 点击「识别并导入候选」：本机 Vision OCR 显示可查看的原文及商品、商家、订单号、购买日期、金额；可选文字 PDF 由 PDFKit 提取，无文字页面才 OCR。支持的事实均可手填、编辑、逐项确认并保留出处。再次识别不会覆盖已确认字段。
3. 样例没有签收日：该字段留空，不根据条款日期推算截止日。日期事实填写 `YYYY-MM-DD`，无效日期不会保存。
4. 可保存「待补日期」行动，不请求通知权限、不排期。只有勾选「我已确认具体提醒日期和时间」并选择未来时间，才在保存后申请系统授权并排期。权限拒绝时订单和行动仍保留，界面明确显示通知未开启。
5. 从「事务」查看事实、凭证及行动，从「待办」按状态跟进。编辑时间替换同一条系统请求，完成或取消行动会撤销待发送提醒。通知仅显示通用文案；点击打开相应事务。通知发送不代表行动已完成。

扫描 PDF 最多 OCR 12 个无文字页面，超出时明确提示；多帧图片只处理首帧。复杂表格可能需要手动校对。疑似密码、恢复码、账号文件名在读取正文前拒绝识别。真实构建、23 项测试和界面记录见 [M3 证据](evidence/M3/README.md)。

## M4：四类事务与允许的正文搜索

1. 添加 `fixtures/M4`，分别选择合成合同、保修、订阅 PDF，从凭证创建事务并选择对应类型。四类共用事实校对、凭证关联和行动编辑；已有事务的类型保留不变。
2. 点击识别只提取原文明确写出的字段；日期和条款仍是候选。缺失的生效日或签收日保持未知，保修期限和续订条款不会自动变成确定提醒日期。TXT/Markdown 也可显式读取，限 1 MiB、200,000 字符，超限明确拒绝。
3. 本机模型是可选按钮，运行时检查系统能力；候选必须有精确原文引用，不能凭空编造值或日期。本机实测为设备不支持模型，生成路径未验证，手动与显式字段提取已完成真实验收。
4. 正文默认不存。识别后点击「保存此正文供全文搜索」，或在文件详情点击「识别并保存正文以供搜索」，才把该份普通凭证的正文保存在本机。疑似密码/恢复码/账号文件名拒绝进入正文索引和模型。
5. 工具栏「搜索范围」启用「搜索已允许保存的正文」后，名称/路径搜索会同时查询 FTS5 正文；支持中文短词。默认搜索仍只查名称与路径。可在详情移除正文索引，原文件不变；已允许的索引重启后保留。

M4 使用系统 SQLite FTS5 trigram，只有明确保存的正文进入索引。四类真实 GUI、36 项测试与本地截图记录见 [M4 证据](evidence/M4/README.md)。

## M5：照片与敏感资料

1. 在「照片图库」主动连接，系统授权后读取真实照片的文件名、日期及本机缓存预览。可选照片关联「我的电脑」，空格放大预览。仅使用 PhotoKit 只读 API，不进入图库包，不修改照片，也不下载 iCloud 原片；大资源不可用时尝试本机缩略缓存。
2. 图片仅在内存中展示，不导出照片副本，不做照片 OCR、模型处理或正文索引。「打开照片 App」打开系统应用本身，可按文件名和日期查找，不宣称精确跳转某张照片。
3. 访问失效时对象关系和照片记录保留不可用占位，文件资料库继续可用。重新授权后点「刷新照片」，只恢复实际返回的照片。
4. 文件名或凭据类型触发「疑似敏感」。详情中可选普通、疑似敏感、敏感；非普通资料拒绝正文识别、FTS 保存和模型。标记敏感会立即删除已有正文索引；名称和路径仍可搜索。明确改回普通后，用户必须再次主动索引。已有手工校对事实保留。

真实记录见 [M5 证据](evidence/M5/README.md)。本地 ad hoc 开发构建代码改变时，macOS 可能再次要求 Photos 授权；正式发行需要稳定 Developer ID 签名。

## M6：备份、规模与本地分发

1. `⌘,` →「备份」→「导出备份」：保存到用户选定的新目录。官方 GRDB/SQLite backup API 建立一致性快照，仅复制该快照引用的 Vault 凭证，逐文件计算 SHA-256，生成版本化 manifest。备份含明文数据库与允许保存的正文，应放在可信位置；外部原件和照片原图不在备份内。
2. 「选择备份并恢复」先核对完整清单、文件哈希、SQLite 完整性和托管引用，再复制到应用内全新独立测试库。始终不覆盖当前资料库，不使用原来源书签，也不重排通知。在「查看恢复资料」中可预览、搜索和用默认应用打开恢复的托管凭证。
3. 实测 10,000 个合成小文件：原生扫描器首次/重扫均约 2.08 秒，唯一名称查询中位数约 5.11 毫秒。此为 CLI `-O` 工具链接 Debug GRDB，不能当成 GUI 或 Release 性能；可用 `scripts/benchmark_scan.swift` 重现。
4. 原生绘制 App 图标、版本 0.6.0 (6)、Release ZIP 与 SHA-256 打包脚本已提供。`scripts/package_release.sh` 构建并打包，已有 Release 时可传 `--skip-build`。本机未发现 Developer ID Application 签名身份，Developer ID、公证、DMG 与干净账户验收未完成，不修改 Gatekeeper 或隔离属性。

最终构建、49 项回归、真实备份恢复及发行限制见 [M6 证据](evidence/M6/README.md) 和 [发布说明](RELEASE_NOTES.md)。

## M7：快速收纳与待整理

1. 从 Finder 将一份或多份普通文件拖到主窗口内容区；也可用「文件 → 收纳文件…」（`⇧⌘I`）、工具栏或待整理空状态的按钮，通过系统文件面板多选。
2. 收纳在后台复制到现有 Vault，SHA-256 校验后才写入同一 SQLite 资料库。每份成功的文件立即出现在「待整理」，可按名称、导入时原路径搜索，并直接预览和打开托管副本。退出重启后仍可用，原位置无需持续授权。
3. 在资料详情关联已有个人对象，或从「从此凭证创建事务」选择订单、合同、保修、订阅。关联后移出待整理，仍在「所有资料」「已托管」及对应对象/事务中保留；解除全部关联会重新回到待整理。
4. 只复制，不移动、修改或删除原件。显示原路径仅供参考，不保存外部文件授权、不自动扫描其父目录。拒绝目录、包、符号链接及网络 URL；同名和重复收纳各保存独立副本。不自动 OCR、索引正文或分类，原有敏感保护继续生效。
5. 批量操作逐份提交，失败会显示文件名和原因；已成功收纳的副本保留。本轮不增加自动导入、文件夹监控或去重。

工程入口仍为 `PersonalSpace.xcodeproj`。验收用 `fixtures/M7` 中明确标记的三份合成文件，应用不会自动导入；构建、测试和真实操作记录见 [M7 证据](evidence/M7/README.md)。

## M7.1：移除误收纳的文件

快速收纳文件的右键菜单和详情页提供「从 PersonalSpace 移除…」。确认弹窗说明将永久移除记录、允许保存的正文和 Vault 托管副本，原位置文件保持不变。已关联对象、事务或事实出处的凭证必须先解除关联。普通来源文件和照片没有这个操作。

数据库先事务检查关联并提交移除，之后才删除经路径校验的 Vault 副本。数据库失败时不碰副本；副本删除失败会明确提示「记录已移除，副本仍保留」并提供本次操作的手动重试，不宣称完整成功。列表、待整理计数和搜索会立即重新查询。相关构建、测试及实机记录见 [M7.1 证据](evidence/M7.1/README.md)。

## M8：一个事务管理多个行动

「编辑事务与行动」中可添加多条行动；详情与待办也可单独编辑、完成或取消。每条行动保留自己的 ID、标题、行动日期、明确确认的提醒时间和状态。未知时间先保存为待补日期，不自动推算。

事务标题、事实和凭证编辑只提交改过的行动；未修改行动不被重写。每个系统通知使用对应行动的稳定 ID，修改或完成 A 不影响 B。详情从实际 UserNotifications 请求读取「系统待发送」时间，权限拒绝或无请求时显示真实状态。点击通知进入对应事务，并滚动、高亮相关行动。沿用已有多行动表，无新增数据库迁移；原有单行动事务可直接读取和编辑。

版本 0.8.0 (9)。实际构建、63 项回归、真实界面与通知验收记录见 [M8 证据](evidence/M8/README.md)。

## M8.1：提醒恢复与行动编辑文案

待办和事务详情中，待处理、已确认未来提醒时间且系统无请求的行动可主动「重新安排提醒」。操作复用现有通知接口，只处理该行动，完成后重新读取真实系统请求；通知未开启时明确提示。不会修改行动日期，也不自动恢复或周期性重建提醒。

在事务编辑的行动子窗口点「完成行动编辑」只更新父事务草稿，并提示「修改将在保存事务后生效」；取消父事务会丢弃修改。待办和事务详情的单行动编辑仍是立即「保存行动」。版本 0.8.1 (10)，实测结果见 [M8.1 证据](evidence/M8.1/README.md)。

## M9：授权文件夹自动更新

添加文件夹后，应用运行期间使用原生 FSEvents 监听该来源。新增、修改、更名和移走文件会自动反映在列表、搜索与选中详情中；移走的原路径保留不可用记录，放回原路径可恢复。来源设置显示实际监听状态，手动「刷新」与「停止扫描」继续保留。

每个来源约 1 秒合并变化后复用现有扫描器。同一来源不并行重扫，扫描期间有新变化最多追加一次；不同来源独立处理。新增、重新授权与重启恢复监听，启动同时补扫；移除来源停止监听。只读授权目录，跳过隐藏文件、包和符号链接，不自动读取正文。对象、事务、事实关联和 Vault 副本保留不变。

版本 0.9.0 (11)，真实 Mac 的 1,000 / 10,000 文件、Finder 操作与重启验收见 [M9 证据](evidence/M9/README.md)。

## M9.1：全文索引新鲜度

已授权文件的大小或修改时间变化后，旧正文和 FTS5 词条在扫描事务中失效；详情提供「重新识别并保存正文」。无变化刷新保留索引，原件不可用或来源报错时不使用旧正文命中，原资料与事实关联保留。快速收纳副本不受来源扫描影响。版本 0.9.1 (12)，构建、真实 GUI 与测试限制见 [M9.1 证据](evidence/M9.1/README.md)。

## M10：恢复并继续使用资料库

在「设置 → 备份」中可分别导出、验证并查看，或「恢复并启用此备份」。确认备份日期、资料/事务/托管数量后，应用恢复到新的内部目录，校验数据库与 Vault 后记录下次启动选择。退出重开即可继续搜索、编辑对象与四类事务、管理行动、收纳文件和再次导出。当前资料库不会覆盖；同一设置页可查看保留的旧库并在下次启动切回。

恢复的文件夹标为「需要重新授权」，重新选择对应文件夹，可使用新路径，原 Source ID 与资料关联保留。原件不存在时保留历史资料及凭证；托管副本可直接使用。照片关联保留但需检查当前设备权限与标识，系统通知按当前资料库读取，不自动安排；未来行动缺少请求时可主动「重新安排提醒」。备份是明文，不含外部原件和照片原图。

默认资料库仍使用原目录；恢复库位于沙盒 `Application Support/PersonalSpace/Libraries/<UUID>`，该目录包含 `library.sqlite` 和 `Vault`，`active-library.json` 保存下次启动的选择。版本 0.10.0 (13)。实际验收与限制见 [M10 证据](evidence/M10/README.md)。

## 一句话定义

PersonalSpace 让用户从 Mac 上散落的文件和照片中，**找到资料、组织个人对象、关联事务、采取行动**。它是个人数字空间的统一入口，而不是 Finder、Photos 或 Passwords 的克隆。

## 核心模型

```text
来源（Source）
  └─ 资料（Item：文件/照片/归档副本）
      ├─ 关联个人对象（Object：设备、房屋、个人档案…）
      └─ 支撑事务（Matter：订单、合同、保修、订阅）
          ├─ 事实（Fact：购买日期、条款…）
          └─ 行动（Action：续订前检查、到期提醒…）
```

用户不需要理解这些开发术语。应用中的主导航是「概览、资料库、个人对象、事务、待办」。未实现的页面暂时不露出无效按钮。

## 六个可验收里程碑

| 里程碑 | 真正交付给用户的能力 | 一句话验收 |
|---|---|---|
| **M1** 先找得到 | 添加文件夹、扫描、按名称搜索、预览、Finder 定位、重启保留 | 找回两个不同文件夹中的真实文件 |
| **M2** 再整理起来 | 创建个人对象、关联资料、手动托管重要凭证 | 一个设备关联两份凭证，归档副本可用 |
| **M3** 开始跟进 | 一张订单 → OCR/手动校对 → 确认日期 → 系统提醒 | 真实的订单提醒能建立、修改、取消 |
| **M4** 扩展价值 | 四类事务、按需全文搜索、可用时的本地模型辅助 | 合同/保修/订阅沿用同一业务路径 |
| **M5** 覆盖个人空间 | Photos 只读关联、敏感文件标记 | 照片可关联；密码样本不进入普通文本索引 |
| **M6** 可长期使用 | 备份恢复、性能、原生 UI、可访问性与分发 | 可恢复一份托管凭证；打包可在 Mac 运行 |

第一轮 **只做 M1，不做 M1 之后的空架构**。后续根据真实用户路径完成下一个能力。

## 非目标

不用 Electron / Tauri / WebView 做主界面；不做云服务、账号、跨端同步、全盘无授权扫描、自动移动删除原件、密码保险箱、通用 Agent 平台。Foundation Models 是可选增强，不得成为手动流程的前提。

## 成功的判定

不是创建多少文件、多少协议、多少状态或多少测试，而是用户能否**在真正运行的 Mac 应用里完成事情**。构建与验收结论只能根据实际运行得出；无法在当前环境执行时写「未验证」，不可声称已完成。
