# 01 · 产品定义（面向真实个人任务）

## 1. 产品定位

**PersonalSpace = 个人数字资料中心 + 个人对象档案 + 事务跟进。**

用户的重要内容分散在 Downloads、Documents、Desktop、自建文件夹和 Photos 中。应用不试图接管所有内容的存储，而是帮助用户完成三个动作：

- **找得到**：从多个授权来源快速找到文件、照片或凭证，并打开原件。
- **理得清**：将资料关联到「我的电脑」「房屋」「个人档案」等对象，一个对象可有多份材料。
- **跟得上**：识别订单、保修、合同、订阅中的有用事实，帮用户确认未来需要采取的行动。

用户为“普通 Mac 用户”，不是企业文档管理员。核心产品不依赖 AI；AI 是减少录入量的可选能力。

## 2. 三个真实使用场景

### 场景 A：找回散落文件（M1）

用户在应用里选择 Downloads 和 Documents。应用扫描文件名、类型、大小、修改日期，列出真实内容。用户输入「合同」，选择结果，在预览中查看文件，再点击「在 Finder 中显示」。再次打开应用时仍能找回。

> 用户价值：不知道文件具体在哪，也能在一个入口查找。第一版按文件名/路径搜索，明确写出能力，不冒充全文智能检索。

### 场景 B：一个对象对应多份材料（M2）

用户创建「我的 MacBook」，把订单、发票、保修凭证关联上去；把最重要的订单复制到应用托管库。以后打开资产页，就能在一处找到相关材料，源文件不变。

> 用户价值：从目录组织升级为现实对象组织。一个文件可关联多个对象，关系只是本地数据库记录。

### 场景 C：一张凭证成为行动（M3）

用户选中耳机订单，点击「创建订单事务」，应用从图片 OCR 或 PDF 提取文字，预填能确认的字段；用户修正购买日期、输入明确的提醒日期，保存一个「保修到期前检查」行动。通知到来时回到事务并可打开凭证。

> 用户价值：凭证不再只是被动存储。缺少签收日期时不自动算退货截止日。

## 3. 产品信息范围

| 内容 | 我们做什么 | 明确不做什么 |
|---|---|---|
| 普通文件 | 用户授权目录内扫描、搜索、预览、关联 | 替代 Finder、自动移动清理文件 |
| 重要凭证 | 归档复制、关联、订单/合同提取、提醒 | 自动执行退款、付款、理赔 |
| 个人对象 | 设备、资产、个人档案及相关文件 | 全能 CRM/资产会计系统 |
| Photos 里的照片 | PhotoKit 授权后只读显示与关联 | 遍历 Photos 库包、自动大规模人脸识别 |
| 账号密码类资料 | 提示疑似敏感、关联安全入口、原件定位 | 密码明文收集、Keychain/Passwords 数据抓取、密码保险箱 |
| 待办/到期事项 | 与凭证关联的日期和本地提醒 | 替代完整日历、自动操作第三方服务 |

## 4. 用户可理解的核心对象

- **资料**：文件或照片的入口，可预览并回到来源；托管凭证可有应用自身的副本。
- **个人对象**：现实里的设备、房屋、证件档案、账号档案等，用来聚合相关资料。
- **事务**：一次购买、保修、合同或订阅。可选关联对象和多份凭证。
- **关键事实**：资料上可读到并需用户确认的商家、订单号、日期、条款等。
- **行动**：一个明确的下一步，如「11 月 5 日前检查续约」，可安排提醒。

用户导航不出现“Source / Item / Fact”等数据库名。

## 5. 版本范围及主次

### 第一阶段必须打通（M1–M3）

1. 资料库：选择目录、扫描真实文件、名称搜索、预览和 Finder 定位。
2. 个人对象：手动创建并关联跨目录文件；重要凭证复制托管。
3. 订单事务：PDF/图片提取、校对、手动确认日期和通知提醒。

### 产品 V1 补齐（M4–M6）

4. 另外三类事务：保修、合同、订阅，沿用相同结构。
5. 普通资料按需正文搜索、系统模型可用时辅助填写。
6. Photos 只读索引与关联；疑似敏感资料安全标记。
7. 真正可恢复的备份；性能、视觉、键盘与发布打磨。

### 不进入 V1

云账号、同步、iPhone、全盘常驻扫描、浏览器密码抓取、自动分类所有照片、强制聊天入口、全自动办理售后、企业协作、插件市场、复杂规则引擎。

## 6. 产品原则按优先级

1. **能完成任务**：每个导航和按钮通向真实行为。
2. **高质量 Mac 体验**：原生窗口、布局、菜单、搜索、选中与焦点符合习惯。
3. **最少认知成本**：用户无需学习资料分类学；尽量从已有文件给出可编辑建议。
4. **不更改原文件**：默认读取与引用；用户明确选择时才复制到托管库。
5. **保留证据**：AI 提取只能给建议，确认事实能回到原文件。
6. **渐进扩展**：既不要做一次性 demo，也不要提前搭通用平台。

## 7. 成功判断（真实可演示）

- M1：用户可以在两个授权文件夹中找到至少 1 份真实文件、打开原件，重启后资料还在。
- M2：一个对象关联至少 2 份来自不同位置的资料；托管后测试源文件移走，副本仍可打开。
- M3：一张订单可以形成用户确认的到期行动，提醒日期可以改动，通知状态反馈真实。
- M4：四种事务不用四套相互冲突的界面或数据库；模型缺席时仍可操作。
- M5：用户能从照片库选择一张照片关联对象；疑似密码文本不会自动进入全文索引。
- M6：导出备份后用空白测试环境恢复，再找到先前托管的凭证。

**指标不是“代码覆盖率达到 100%”，也不是“文件数达到多少”。** 先以真实可用结果检验，再依据实测决定性能优化。
