# 02 · 页面和交互（所有可见操作都要可用）

## 1. 完整产品导航，以及逐步开放原则

```text
PersonalSpace
├── 概览（有资料和行动时逐渐启用）
├── 资料库  ← M1 起的首要工作区
│   ├── 所有资料
│   ├── 待整理（M3 后候选事实）
│   └── 来源（选择的文件夹 / 后续 Photos）
├── 个人对象  ← M2 起
├── 事务      ← M3 起
├── 待办      ← M3 起
└── 设置      ← M1 起有真实来源管理
```

**不要第一轮就把完整导航都做成灰色按钮。** M1 仅展示资料库及真正可用的设置；新增功能完成后再出现。以后每个导航都有清晰的空状态和一个实际主操作。

## 2. 通用工作区

采用原生 `NavigationSplitView` / `Table` / Toolbar：

```text
┌───────────────────────────────────────────────────────────────────────────┐
│ Mac 标题栏 / 工具栏              资料库        搜索        添加文件夹  ⋯ │
├────────────┬─────────────────────────────────┬──────────────────────────┤
│ 资料库     │ 文件名     种类  修改日期  来源 │ 合同-租房.pdf             │
│            │ --------------------------------│ [原生文件预览]          │
│ 来源       │ 合同-租房.pdf    PDF        Docs │                          │
│ Downloads  │ 耳机订单.png     图片       Down│ 文件信息                 │
│ Documents  │ 发票-电脑.pdf    PDF        Docs │ 来源：Documents          │
│            │                                 │ 打开原件  Finder 中显示 │
└────────────┴─────────────────────────────────┴──────────────────────────┘
```

- **左侧**：导航与来源。当前工作区显著，但不用彩色卡片墙。
- **中间**：主要工作列表；文件优先使用 Table，真实列排序和选中状态。
- **右侧**：选中结果的预览、信息与动作；用户不需要跳十几页才能打开文件。
- **工具栏**：高频操作「添加来源、搜索、打开」，最多必要的几个；较少用动作放右键菜单/更多菜单。
- **窗口**：栏可隐藏，窄窗口把详情折叠成 Inspector 或独立详情视图；不能裁断主操作。

### M1 最重要的页面

**资料库 / Library**

- 添加文件夹：`NSOpenPanel` 选目录，支持多次添加。每个来源显示名称、已发现文件数、最后扫描时间。
- 扫描：文件先逐步出现，允许继续搜索已索引内容；进度显示「已发现 N 个文件」，没有确定总量时不虚构百分比。
- 搜索：输入文件名或路径关键字即可筛选；可按来源、类型、修改时间排序。
- 列表：名称、类型、来源、修改时间；大文件不预先解码全文。
- 详情：系统预览或适合格式的原生预览，完整路径、大小、修改时间，`在 Finder 中显示` / `打开`。
- 用户重启应用，来源及索引仍在；用户可手动刷新来源。移动文件后刷新显示对应条目不可用，不误删整个历史。

**来源设置 / Sources**

- 每个来源有添加、重新授权、刷新、移除来源操作。
- 「移除来源」删除本应用关于该来源的索引记录，但永远不删除原始文件；关联的事务凭证若失效，显示来源不可用占位而非删除用户创建的对象。
- 用户取消授权弹框无需弹出错误警告。无权限时清楚提示「重新选择此文件夹」。

**第一次启动 / Empty State**

标题「把散落的个人资料放到一个入口」，说明「文件保留在原位置，仅建立本地索引」，一个主按钮「添加文件夹」。不展示虚构订单、虚构库存和 KPI。

## 3. M2：个人对象与托管归档

**对象列表**：名称、类别、关联资料数。第一种可用对象是「设备」，同时保留简单“其它”类型，不强制用户选择复杂分类。

**对象详情**：标题、备注、关联资料。用户可选择多个资料，点「关联到对象」，也可以在对象详情点击「添加已有资料」。同一资料可以关联多个对象，不改变源路径。

**托管归档**：选中重要凭证 → 点击「保存副本到资料库」→ 应用复制文件到私有 Vault → 成功后详情同时显示「原文件」与「托管副本」可用状态；用户可以打开托管副本。原件被移动不影响副本。

避免在这个阶段做复杂的查重建议、自动合并、关联图谱编辑器或“智能资料分类仪表盘”。

## 4. M3–M4：事务与待办

**事务列表**：订单、保修、合同、订阅，可按类别与状态过滤。默认按最近更新排序，清楚显示下一个行动。

**事务详情**分四段：

1. 是什么：标题、类别、相关对象、状态。
2. 有什么凭证：关联的原件与托管副本，点击可预览。
3. 已知道什么：关键事实（值、是否确认、从哪份资料提取）。
4. 需要做什么：Action 标题、日期、提醒状态、完成按钮。

**从订单截图创建事务的操作**：

1. 选中文件，点击「创建订单事务」。
2. 若是 PDF，先尝试文本提取；若是图片，按需执行 Vision OCR；文字展示在侧边供用户参考。
3. 基于识别内容预填商品、商家、购买日期、订单号等**候选**；用户可以直接更正，不需要进入多层审核界面。
4. 用户确认事实，填写具体截止日期或只创建「待补日期」行动。
5. 用户启用通知后保存提醒；若系统拒绝通知，行动照常保存并显示「未开启系统通知」。
6. 在事务详情点原件，能找到创建行动时的材料。

**重要语义**：购买日期与签收日期不是一个字段；合同自动续期不等于可以无条件推断取消截止日期。未知时显示「待确认」，不计算看似精确的日期。

**待办页面**：按「即将到期」「需要确认日期」「已完成」分组。编辑日期时重排提醒；完成后取消待处理通知。系统通知成功投递不等于行动完成。

**概览页面**：有行动后展示今天和将要到期；有待整理事实时展示待确认；其它内容按最近使用、来源状态分组。不使用装饰性图表和零值 KPI。

## 5. M5：Photos 与敏感资料

**照片**：在来源中由用户明确添加系统图库；PhotoKit 只读展示允许访问的日期和缩略图。选中照片后「关联到对象」。不提供全图库内容 AI 识别/批量上传。

**疑似敏感资料**：文件名包含「密码」「恢复码」「账号」等候选，标记为“可能敏感”，不执行自动正文提取；用户可标记为普通/敏感，点击后可主动「在 Finder 中显示」或「打开原件」。应用不是 Apple Passwords 替代品，不提供密码明文摘要或密码搜索。

## 6. 交互一致性

| 操作 | 原生行为 | 第一出现阶段 |
|---|---|---|
| `⌘F` | 聚焦当前列表搜索 | M1 |
| `⌘,` | 打开设置 | M1 |
| `Space` | 预览选中的文件（Quick Look 或原生预览） | M1 |
| `Return` / 双击 | 打开原件或进入当前条目 | M1 |
| 右键 | 展示当前条目实际支持的操作 | M1 |
| `⌘N` | 在对象/事务页创建对应实体 | M2/M3 |
| 拖放 | 将 Finder 文件/文件夹导入或添加来源，语义明确 | M2 前后 |

菜单、右键和工具栏操作应调用同一动作逻辑。暂未实现的动作直接隐藏，不做展示无效按钮的“预告版产品”。

## 7. 少量真正需要的反馈状态

- **无来源**：添加文件夹。
- **扫描中**：已发现文件数、当前来源、可继续浏览；手动刷新可重新执行。
- **无搜索结果**：清除搜索或换一个关键词。
- **文件找不到**：保留资料信息，提示「原位置已不可用」，可重新选择来源。
- **识别失败**：展示可手动填写的事务表单，不必先修复 AI。
- **提醒未授权**：行动已保存，但提示打开通知权限，不能显示“提醒已设置成功”。
- **托管失败**：明确复制失败，原件不会改变。

不提前建设十几种内部状态、七层警告与统一报错框架；新增状态需要当前用户能遇到的真实场景。

## 8. 页面完成标准

- 用户能用鼠标和键盘完成当前里程碑路径；打开文件和预览是真实结果。
- 普通文字/日期/按钮尺寸遵循 macOS 习惯；布局不仿网页 Dashboard。
- 打开应用看到真实数据，不需要先通过 AI 对话才能开始使用。
- 页面不承诺尚未实现的能力。
