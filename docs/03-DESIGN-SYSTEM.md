# 03 · 原生、成熟、耐看的 Mac 设计系统

> 设计方向：**Calm · Precise · Native**。专业感首先来自信息结构、操作效率和微细节，不来自大面积品牌色、渐变和复杂动画。

## 1. 对“专业”的明确要求

用户打开应用的前十秒应能判断：这是一个认真做过的 Mac 应用，而不是网页套壳或 AI Demo。

五个必要条件：

1. 系统标题栏与 Toolbar，正确的窗口缩放、侧栏折叠和菜单栏。
2. 文件使用真正的列表/Table，列排序、选中、右键、键盘焦点一致。
3. 右侧详情展示可见的原件预览、来源信息和**真正可点击的操作**。
4. 视觉层级稳定：主内容清楚、次要元信息弱化、空状态有单个明确主动作。
5. 有数据、无数据、搜索无结果、来源断开都不是临时拼出来的警告弹框。

## 2. 系统组件优先，不自创控件

使用 SwiftUI `NavigationSplitView`、`Table`、`List`、`Form`、`Toolbar`、`searchable`、系统 `Button` / `Menu` / `DatePicker`、SF Symbols。文件选取与 Finder 使用 AppKit。预览优先系统 Quick Look（集成成本过高时暂用成熟的系统预览入口，不能伪造一个图片框）。

常规按钮、日期控件、文本输入和菜单不自绘；窗口菜单快捷键用 macOS 原生 Command 系统。

## 3. 布局基线（允许实机调整）

| 区域 | 初始建议 | 关键行为 |
|---|---|---|
| 窗口 | 1160 × 740 pt | 用户可缩放；保存系统窗口状态 |
| Sidebar | 190–240 pt | 隐藏或调整宽度；来源不占满整个导航 |
| 列表 | 420–610 pt | 文件名有足够宽度；列标题可排序 |
| 详情 | 320–440 pt | 预览与信息可滚动；小窗可折叠 |
| 内容间距 | 8 / 12 / 16 / 24 pt | 以系统控件自然间距为准 |
| 文件行 | 约 32–36 pt | 视觉紧凑、支持动态字体 |

窗口尺寸不是不可变硬编码。如果 `NavigationSplitView` 在窄窗口自然折叠，就遵循系统行为，不用一堆自定义宽度计算维护三栏。

## 4. 视觉规范

### 字体和层级

- 使用 SF 系统字体和 SwiftUI 语义文本样式，不在每个组件硬写固定字号。
- 资料标题强调（`.headline`）；类型、时间、大小、路径使用 `.secondary`；正文不为了“精致”统一压成 11pt。
- 列表信息整齐可扫读：日期/大小列尽量右对齐，长文件名合理截断且 hover/Inspector 可查看完整名。

### 颜色与材料

- 默认遵从系统强调色、浅色/深色和系统语义背景；不要强制暖白底色覆盖所有区域。
- 自有品牌色仅用于应用 Icon、欢迎页少量视觉焦点；不让一个品牌红取代警告/成功的系统语义色。
- Sidebar 使用系统侧栏材质；列表/详情以原生分隔线和信息组界定，不铺满巨型圆角卡片。

### 图标和空白

- 使用 SF Symbols，类型图标优先采用系统文件类型图标。
- 图标要表达动作，不滥用“AI 星芒”“机器人”“魔法棒”。
- 空状态留白可以多，但要有清楚的下一步；有资料时信息密度要像成熟文件工具，而不是宣传落地页。

## 5. 核心页面的具体设计

### 文件库（M1）

**工具栏**：左侧标题“资料库”，右侧添加文件夹、搜索、必要筛选。主操作要稳定，不在每条文件行放三个彩色按钮。

**列表**：文件图标与名称第一优先；右侧是类型、修改日期和来源；行选中态由系统管理。可以多选，但 M1 只做已有真实多选操作，不抢做批量管理栏。

**详情**：

1. 文件名 + 类型/大小；
2. 预览区域（适合的图片或 PDF）或系统预览入口；
3. 核心动作「打开」「在 Finder 中显示」；
4. 来源、路径、日期等属性分组。

当文件缺失，保留详情，预览换成清晰说明与一个“刷新/重新授权”动作；不让整个应用出现红色 Error 500 页面。

### 个人对象（M2）

设备对象详情：标题、少量手填属性、关联文件列表。设备照片可选，没照片就用系统图标，不用 AI 生成装饰图。

### 事务与行动（M3）

主信息始终是「哪件事」「确认了哪些信息」「下一步做什么」「依据在哪」。显示来源/候选状态时使用轻量标签和原生编辑控件；AI 不能抢占整个页面。

### 设置

按来源、通知、数据和关于组织。控件与描述宽度一致；不复制 iOS 的大卡片设置风格。已经没有实际功能的设置不要展示。

## 6. 不要做这些

- Hero Banner、KPI 数字墙、大圆角渐变卡片、滚动聊天输入框。
- 为普通文件搜索加入“AI 思考中”假动画。
- 用一个自绘控件替换标准 macOS 按钮、侧栏、表格。
- 扫描时显示靠定时器增长的虚假百分比。
- 把所有错误做成模态弹窗，要求用户连续确认。
- 每个里程碑推倒已有布局重新设计一套组件库。

## 7. 细节验收（按阶段适度）

**M1 要至少提供实际运行的**：

- 空状态（添加文件夹按钮）截图；
- 有真实文件的资料库 + 右侧详情截图；
- 浅/深色之一作为主测，另一种在本阶段快速检查是否有不可读问题；
- 操作演示：选文件、搜索、打开、Finder 定位、窄窗口可操作。

**M2–M4** 增加对应对象和事务页面截图，检验真实数据状态。

**M6** 才全面检查浅/深色、高对比度、VoiceOver、键盘、长文件名、不同屏幕尺寸，并形成发布截图。

截图是检查界面布局的工具，不是项目门禁；如果当前机器无法抓取 GUI，明确未验证，先交付能运行的代码和最短复现步骤。

## 8. 实现层面的小建议

- 可复用的界面组件只抽：空状态、文件行、详情属性行、状态提示、事项日期编辑；不要一开始做 40 个 DesignSystem View。
- `.help()`、快捷键、菜单项 title 保持准确；正常状态减少 toast。
- `NSWorkspace` 处理 Finder 与默认程序操作；遵守系统选中文件和焦点行为。
- 禁止为达到截图效果写入生产数据库的虚构文件名或事项。
