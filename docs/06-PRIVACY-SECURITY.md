# 06 · 安全与隐私：必要而有限，不做安全工程表演

**原则**：产品接触个人文件、合同和账户资料，必须有少数明确底线；但不为遥远的假设建立复杂防御架构。

## 1. 四个不妥协的边界

### 不破坏原件

- 默认扫描/索引只读；不提供自动重命名、移动或删除用户源文件。
- 重要资料托管是复制。成功后仍保留原始路径及副本路径。
- 归档过程中复制失败，不能显示成功，更不能更改原文件。

### 不越权读取

- 用户选择了哪个目录，就访问那个目录及其正常子项；不尝试读取其他 App 私有容器、系统 Keychain 或绕过沙盒。
- 扫描跳过目录包和指向授权范围外的符号链接。
- Photos 只经 PhotoKit 授权获取；不能进入 `.photoslibrary` 包的内部结构。

### 不泄漏秘密

- 普通扫描默认索引文件名和元数据，不批量读取所有文档正文。
- 文件名或用户标记为疑似密码/恢复码的资料，禁止自动 OCR、普通 FTS 正文索引、模型提示词与通知摘要。
- 日志仅记录内部 ID、错误类型与数量，不记录密码、合同正文、订单号、搜索词或完整个人文件路径。
- 发现敏感资料是**提醒用户管理风险**，不是承诺能完整识别电脑里所有密码。密码本身交给 Apple Passwords 等专用工具管理。

### 不制造假事实与假成功

- AI 提取的日期属于候选，签收日未知就不能推断退货截止日。
- 未经用户确认的截止日期不安排提醒。
- 通知权限拒绝，必须显示「行动已保存，但系统通知未开启」；复制/数据库提交失败也不能说“已完成”。

## 2. 具体的权限交互

| 操作 | 触发授权的时机 | 用户取消后 |
|---|---|---|
| 添加目录 | 点击「添加文件夹」，系统选择窗口 | 回到原界面，不报错 |
| 打开已授权文件 | 通过安全作用域 bookmark 获取访问 | 保留索引项，显示重新授权 |
| 连接 Photos | 点击「连接照片图库」 | 继续使用文件资料库 |
| 安排提醒 | 用户首次明确保存需通知的 Action | 保存 Action，显示通知未启用 |

不要在启动时一次弹出全部系统权限请求；每项能力用到时再申请。

## 3. 只做对应功能需要的错误处理

**M1** 处理：目录授权失效、文件不见了、无法打开原件、扫描取消。

**M2** 新增：复制失败、托管副本不存在。复制时临时文件写入，完成后进行一次校验。

**M3** 新增：OCR 失败可手填、通知未授权不假成功、日期缺失不排期。

**M5** 新增：PhotoKit 拒绝、用户标记敏感后普通全文索引不包含正文。

**M6** 新增：备份校验与恢复失败时保留现有数据。

不为每一种可能的 I/O 错误建立单独的状态类、统一恢复总线或多级重试服务；简单 UI 提示 + 用户可重试，足以满足多数实际场景。

## 4. 数据存储与备份

- 资料索引及事务记录使用本地 SQLite；托管文件放应用的 Application Support；索引原件仍在原位置。
- 先保证托管资料可被导出/备份/恢复，再正式发布面向长期使用的 V1。
- 备份至少包含一致的数据库快照和托管原件，附内容校验。恢复先在测试位置验证，成功后才替换活动数据。
- 应用不宣称备份“自动端到端加密”，除非实际实现和测试；用户应清楚知道导出的备份可能包含个人资料。
- 不做密码保险箱、不通过自定义弱加密方案存储用户密码。

## 5. 最小安全测试

1. 选择测试目录后扫描，源文件内容和路径不被移动/改写。
2. 授权目录中放指向外部目录的符号链接，扫描不跟随越界。
3. 创建托管副本并比较 SHA-256；删除**测试源文件**后托管副本仍能打开。
4. 用合成 `密码记录.txt`，检查其内容没有进入 FTS、日志、通知。
5. 订单缺失关键日期，不生成确定截止提醒。
6. 导出备份后破坏测试备份包，恢复拒绝修改现有库。

只有这些出现真实失败，才加针对性保护；不要把安全测试列表无限扩展成一个安全产品工程。
