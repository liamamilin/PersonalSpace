# 07 · 开发路线：M1–M6，每轮交付一个用户闭环

> **这份文件是 Codex 的实施主线。** 先交付可运行能力，不提前建设后期基础设施。所有阶段都有用户场景、必需实现、验收动作和明确不做。

## 开始前（只做一次）

在实际 Mac 上检查：

```bash
xcodebuild -version
swift --version
xcodebuild -showsdks
```

建立一个原生 macOS SwiftUI Xcode App，目标 macOS 26+；启用 App Sandbox，添加 GRDB 作为核心数据库依赖。以当前可用 Xcode 的 SDK 为准确认 API。没有 Xcode 的环境不能宣称已构建或已手测。

不用先完成一个“平台/框架里程碑”；**M1 就包含可运行工程和有真实数据的产品界面**。

## M1 · 找得到：第一轮必须交付

**用户闭环**：用户添加两个文件夹 → 看到真实文件 → 搜索 → 预览 → 在 Finder 中找到 → 重启后仍能查到。

**实现**

1. 原生主窗口 + 资料库 Table + Inspector 详情 + 来源设置。用户可选目录，首次空状态有真实按钮。
2. `NSOpenPanel` 选择目录，保存安全作用域 bookmark；App 重启后能重新访问授权目录。
3. `FileManager` 扫描文件名、类型、大小、修改日期和路径；后台批量写入 SQLite/GRDB。
4. 文件名及路径关键字搜索、来源筛选、基本排序、选中、预览、默认应用打开、Finder 中显示。
5. 手动刷新和重新授权。文件移走时显示不可用而不是删除所有历史。
6. 原生菜单、至少 `⌘F`、`⌘,`、`Space` 或等效系统预览；窗口调整后主要控件仍可用。

**验收操作**

- 测试目录 A 放 `订单样例.pdf`，目录 B 放 `租赁合同.txt` 和 `设备照片.png`。
- 添加 A、B，搜「订单」和「合同」，各自打开原件并在 Finder 中显示。
- 退出重启，搜索和来源仍存在。
- 把测试文件移走，手动刷新，列表没有崩溃且可看到不可用提示。

**本轮不做**：FSEvents、复杂文件身份、全量 SHA、OCR、全文检索、对象、事务、Photos、备份、AI。

**交付**：真实项目、运行方式、构建/必要单测结果、至少空状态和真实列表两张实际截图（如有 Mac GUI）、未完成项。没运行的不能写“已通过”。

## M2 · 理得清：对象与凭证托管

**用户闭环**：创建「我的电脑」→ 关联两份来自不同文件夹的资料 → 把订单复制托管 → 测试源文件移走后依然可打开副本。

**实现**

1. 对象列表与详情：创建设备对象、编辑名称/备注、关联/解绑资料。
2. 资料库和对象页互相导航，关联只动数据库，不动源文件。
3. 「保存副本到资料库」：复制到 Application Support，计算一次哈希校验，成功才记录托管路径。
4. 原件与副本的打开操作清楚区分。

**验收操作**：用两个测试目录的两份文件完成关联、重启检查、归档、移动测试源文件、打开托管副本。

**本轮不做**：自动去重、资产知识图谱、内容寻址存储、归档垃圾回收器、多位置 Item 合并。

## M3 · 跟得上：第一条订单事务与提醒

**用户闭环**：订单 PNG/PDF → 提取文字 → 校对关键字段 → 填入明确日期 → 保存行动 → 系统提醒 → 从事务打开原件。

**实现**

1. 建 Matter/Fact/Action，先支持 `order`；订单页提供真实编辑功能，不求通用表单引擎。
2. PDF 文本用 PDFKit；图片用 Vision OCR，用户点「识别」才处理。
3. 能从识别文本提议基本字段，识别不准就直接改；Apple 模型不是完成本轮的先决条件。
4. 展示出处和“候选/已确认”区别，缺失签收日不推断截止日期。
5. 用户确认一个具体提醒时间，`UserNotifications` 创建、修改、取消通知；权限拒绝明确显示未启用。
6. 事务详情能看到相关凭证与待办；应用重启后 Action 仍在。

**验收操作**：使用合成订单图片；验证 OCR 原文可看、事实可编辑、未确认日期不会排期；手动确认日期后能安排通知；修改后旧通知取消；从事务回到凭证。

**本轮不做**：四种事务同时开发、自动退款、通用规则引擎、复杂模型重试队列、通知状态机。

## M4 · 更懂资料：四类事务 + 可选智能

**用户闭环**：合同、保修、订阅与订单遵循同一模式：凭证 → 编辑事实 → 明确行动 → 找回原件。

**实现**

1. 在现有 Matter/Fact/Action 上补三类事务的必要字段和少量场景模板。
2. Apple Foundation Models 在实际 SDK 可用时做结构化候选；运行时检查可用性；不可用时完全不阻断用户填写。
3. 对用户选择识别的非敏感文件保存允许的正文文本并做 FTS5，中文短查询至少能通过标题/文件名 fallback 找到结果。
4. 将已有订单页面收敛为共享的事务详情和字段编辑组件，不建立四套数据模型。

**验收操作**：四类各 1 份样本；完成创建、校对、提醒和找回凭证。断开网络或关闭模型时仍可手工完成。

**本轮不做**：整盘自动 OCR、Embedding 向量数据库、聊天式搜索、自动法律判断。

## M5 · 真正覆盖个人资料：照片与敏感资料

**用户闭环**：连接 Photos → 选照片关联「我的电脑」；将疑似密码文档标敏感 → 普通搜索不显示其正文。

**实现**

1. PhotoKit 授权、缩略图/日期展示、从照片选择一张关联对象；只读，不操作图库包。
2. 文件名/类型触发敏感候选，允许用户手动标记；被标记资料不进入普通正文 FTS 和模型处理。
3. 权限失效时保留对象关联的不可用占位，给出恢复入口。

**验收操作**：真实系统图库关联照片；合成密码文件不入 FTS；拒绝照片授权后文件资料库仍可用。

**本轮不做**：自动照片分类、人脸图谱、密码保险箱、读取 Apple Passwords。

## M6 · 可以长期使用：备份、品质与分发

**用户闭环**：保存重要凭证 → 导出备份 → 在全新测试库恢复 → 打开凭证；全程界面成熟、权限文案正确。

**实现**

1. 数据备份/恢复：一致性 SQLite 快照 + Vault + manifest/哈希；验证后恢复，不损坏原库。
2. 全应用 UI 统一：浅/深色、窄/宽窗口、菜单/快捷键/右键、键盘与 VoiceOver 的高频路径。
3. 实测一批大规模文件（例如 10k 小文件）后针对真实瓶颈优化，必要时再引入 FSEvents；不为未观察到的性能问题重写扫描架构。
4. 检查权限丢失、托管副本打开、通知修改、备份恢复等关键回归。
5. App 图标、版本信息、发布说明；证书允许时签名/公证/DMG 干净账户验证。

**本轮不做**：云同步、多端、自动化 Agent、扩展商店。

## 每轮结束时只需报告

```text
阶段：M1
做成了什么：真实功能和对应代码
操作演示：从打开 App 到完成目标的步骤
验证：xcodebuild 命令结果、关键测试、必要真实截图
仍未完成：明确列出（如没有 GUI 无法截图）
下个阶段：M2 的第一条用户路径
```

**报告不等于交付物。** Codex 应先运行程序、解决阻断用户路径的问题，再写简短报告。严禁为了完成额外“审阅门禁”而延后可用功能。
