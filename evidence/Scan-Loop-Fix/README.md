# 大目录反复扫描修复 · 0.10.4 (17)

## 完成能力

用户在整个用户目录上遇到百万级文件扫描、上次扫描错误与持续进度并存。代码检查发现：监听只忽略部分隐藏路径，未排除应用自身的 SQLite 与托管目录；自身写入可以排入下一次全来源扫描。原「停止扫描」取消当前任务，但仍保留监听，新的文件事件会再次扫描。界面中的旧错误也未注明属于上次扫描。

扫描和 FSEvents 现在共用具体排除路径，跳过自身 SQLite 及 WAL/SHM/journal，以及实际应用资料库根目录。目录前缀按路径边界比较，相似名称的用户文件夹仍正常工作。大来源每约 250 毫秒报告已保存的实际数量，结束时报告最终数量，减少每百文件一次全界面查询的积压。

停止扫描会停止监听并把暂停状态写入同一 SQLite，重启后不补扫暂停来源。手动刷新只扫描一次；「恢复自动更新」重新监听并补扫。扫描失败会暂停自动重试，不将旧资料标为缺失；升级时已有错误的来源先暂停，健康来源维持原行为。书签更新保留暂停状态，主动重新授权或重新添加才恢复更新。助手同步支持读取暂停状态和恢复自动更新。

## 用户操作路径

退出旧版，打开 0.10.4。在「设置 → 来源」查看原来源：之前有扫描错误的来源显示「自动更新已暂停」。可以单次刷新，或主动恢复自动更新；运行中点「停止扫描」会停止当前任务并继续保持暂停。建议添加实际存放凭证和文档的具体文件夹。已有文件、个人对象关联、事务与托管副本保留，原件不改动。

## 构建/测试证据

Xcode 27.2。修复前针对性测试真实失败：扫描数据库父目录时，`library.sqlite` 被当作普通资料保存。修复后首轮 18 项扫描和真实 FSEvents 测试通过；完整 95 项回归通过，另补充 1 项旧版升级测试通过。测试源与文件均为明确的合成数据。

新增验证包括：数据库在被扫描目录内时不进入索引、自身连续数据库写入不会引发补扫、内部目录原子写入不触发事件但相似名称的用户目录仍触发、停止后重启与单次刷新不恢复监听、主动恢复后新文件自动出现、取消排队扫描清除补扫并保留历史可用状态、失败后暂停、旧版升级保留对象关联与书签续期保留暂停。

原始日志和 xcresult 保留本机 `.build/Scan-Loop-Fix/`：`before-native` 为预期失败；`scan-tests`、`full-tests`、`upgrade-test` 为通过结果。Debug 与 Release 构建日志分别为 `debug-build.log`、`release-build.log`；测试后已重新构建普通 Debug，恢复非测试宿主签名。
